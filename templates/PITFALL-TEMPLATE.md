## Pitfall N — <one-line rule, imperative, bolded in the index>

**Rule:** <One sentence. If it needs two, you have two pitfalls.>

**Symptom:** <What this looks like from the outside, while it is happening. Written so it is
recognizable in the moment, not only in hindsight.>

**The rationalization:** <THE MOST IMPORTANT FIELD. The reasoning that made the mistake feel
correct at the time, first person, as it actually ran. Usually every clause is true and the
conclusion is wrong — that is what makes it dangerous. A rule without this gets argued around
again, because the next occurrence will not feel like a mistake either.>

**How to avoid:** <Concrete and mechanical. A command, a check, a count, an ordering.
"Be more careful" is not an action.>

**Why it matters:** <The cost, in one or two lines. This is what stops a future cleanup from
trimming the entry.>

**Enforcement:** <Where the rule now lives so it fires automatically — file + step, hook, test,
or assertion. If this line says "the index", the rule is weak; find a better site.>

**Origin:** <Date. What triggered the capture. The user's own words verbatim if they said
something sharp — quotes age better than paraphrase and make the entry findable by memory.>

**Related:** <Cross-references to entries of the same shape. Cross-reference rather than merge,
so both search paths still work.>
